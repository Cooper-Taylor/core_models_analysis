      Analytics

      Cross-cutting maps of all … direction variants and the 100-model panel. Hover any cell / point for exact values; reaction and model ids link into the other tabs.

      Variant agreement — pairwise fraction of reactions with the same direction, over reactions both variants call (excludes shared "?")

      Effect correlation — similarity of variants by their per-model Δ growth effect (not by direction call)

      Reaction-direction makeup — share of forward / reverse / reversible / unknown per variant

      Impact landscape — how many models each variant perturbs vs how many flip grow-status (bubble = reactions changed)

      Growth break vs restore — per variant, models that lose growth (left) vs gain growth (right) vs baseline

      Panel growth heatmap — Δ growth flux of each panel model (rows) under each variant (cols); green = gains, red = loses

      Δ growth-flux distributions — spread of growth perturbation across the models each variant moves

      Enzyme-class rewrites — how many panel reactions of each EC class a variant re-directs

      Reaction criticality — reactions whose direction change disrupts growth in the most panel models (from the key-reaction sweep)

      About

      • Cascade source: ModelSEEDDatabase/Scripts/Thermodynamics/Estimate_Reaction_Reversibility.py ported into core_models_analysis/scripts/reversibility_lib.py behind a ReversibilityConfig knob-set. Defaults reproduce the upstream cascade byte-for-byte.
      • Heuristics review: reports/REACTION_REVERSIBILITY_HEURISTICS_REVIEW.md (revision 2026-06-01, §§ 2.1 / 3.1 / 3.2 / 3.3 / 3.4 / 3.5 / 3.6 / 3.7 / 3.8 / 3.9 / 3.10 + H1–H5). Each variant tag in the browser points at one section. The companion reports/REVERSIBILITY_HEURISTICS_IMPACT.md rolls up the panel + all-models impact data shown here.
      • Panel: 100 descriptive panel models from core_models_analysis/results/selected_ids.txt.
      • Metric — growth (biomass): every FBA maximizes the model's biomass reaction (bio1/bio2). Each open KBaseMedia exchange allows up to -1000 mmol/gDW/h uptake; secretion is unrestricted. JSON keys growth_flux/grows hold the biomass flux and growth status.
      • FBA reference: variants are compared to the heuristic baseline -- panel models fully rebound to the MSDB cascade's defaults. This isolates "what does the heuristic say" from "what does the on-disk model JSON say" (which differ in 98/100 panel models because the JSON bounds are template-time, not always in sync with MSDB).
      • What's not modified: anything under ModelSEEDDatabase/ or core_models_kegg2/. All variant reports live under core_models_analysis/thermo_variants/{tag}/; all rebinding happens in memory.
      • Live FBA: the Flux Sandbox + the Reaction Explorer's "per-variant panel sweep" actually run COBRA FBA via the backend (site/serve.py → scripts/growth_heuristics.py). Each call takes ~5-30 s depending on panel size. The Reaction Explorer's sweep automatically uses the selected variant's new direction for the reaction (no mode picker) and compares against the baseline cascade — one column per panel model containing the reaction.
      • Model scope toggle (Variant Browser): switch between the 100-model descriptive panel and the full 5,683-model core_models_kegg2/ database. The all-models scope shows mean / median / std growth flux, largest gainer / loser models, and how many models flip in either direction. Built by scripts/build_all_models_impact.py.
      • Reaction Explorer filters: filter to reactions changed by a specific variant, with an optional subfilter restricting to reactions whose direction change actually shifts growth flux in at least one panel model containing them.
      • Static mode: this server was launched without the FBA backend. The Flux Sandbox tab is hidden and the Reaction Explorer's per-mode panel sweep is disabled. Run python3 site/serve.py --live after installing cobra and cloning ModelSEEDDatabase as a sibling of core_models_analysis/ to enable live FBA. See the project README for full prerequisites.
